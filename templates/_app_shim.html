{# The two wrappers every page needs, in the only order that works. Behind the gateway this app is served at /terminal, and the templates make ~100 root-relative fetch("/api/...") calls that would otherwise hit the gateway's own root. Rather than touch each one, fetch and XHR are wrapped here to prefix root-relative URLs. Hit directly on its own port, APP_ROOT is "" and this changes nothing. The prefix wrapper MUST install before the CSRF wrapper. The CSRF shim captures window.fetch to fetch its own token from /api/csrf-token; if it captures the raw fetch, that request escapes the prefix, 404s on the gateway, and the token is null -- so every POST goes out with no X-CSRFToken header and the server rejects it. That is one bug ("CSRF validation failed") on every execution path in the product. #} {% include "_csrf_shim.html" ignore missing %}
